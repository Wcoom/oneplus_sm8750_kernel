## 真机故障修复

- 现象：旧内核在 KernelSU sucompat 路径反复触发 `kernel/seccomp.c:576`，采样时 22 次；WARN 后提前返回，filter 引用未释放。
- 根因：ACK 把 Linux 6.11 `bfafe5efa975` 的 `seccomp_filter_release()` 新契约回移到 6.6；官方 KernelSU 仍按 `LINUX_VERSION_CODE` 为 6.6 选择 `sighand=NULL` 的旧临时 task 契约。
- 修复：真实 task 继续要求 `PF_EXITING` 并持 `siglock`；只对 `sighand==NULL` 的已分离快照恢复旧释放路径。无结构体、导出符号或函数签名变化。
- 边界：未删除通用 seccomp WARN；有 sighand 的非退出 task 仍被拒绝。

## 经验补充

- **AnyKernel3 模板 tools 无执行位**：模板目录打包进 zip 时权限丢失（magiskboot 等均为 0644），设备端 /data/local/tmp 解包后 `Permission denied`。刷机前必须 `chmod -R 755 tools`（已修模板源文件，后续轮次免除此步）
- 构建脚本 `内核构建.sh` 依赖调用时工作目录为内核源码根，脱离目录运行会报 `No rule to make target 'gki_defconfig'`
- 版本串固定导致无法以 uname 区分新旧内核：以 boot 分区内核段 md5 与本地 Image 对比为准（boot 头 4096 字节需 skip=1）
